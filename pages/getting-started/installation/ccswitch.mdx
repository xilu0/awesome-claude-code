# 在 CC Switch 中配置 Claude Code

[CC Switch](https://github.com/farion1231/cc-switch/releases) 是一款跨平台桌面应用，在图形界面里统一管理 Claude Code、Codex、OpenCode、Gemini CLI 的多套 API 配置。本页只讲一件事：**在 CC Switch 的「添加供应商」表单里，每个字段到底应该填什么**，让你 90 秒内把 Claude Code 接到 CC Club，省掉手改 `~/.claude/settings.json` 的麻烦。

## 字段详细说明

<Steps>

### 供应商名称 / 备注

随便取，方便你以后在 CC Switch 列表里一眼认出来即可。建议带上「CC Club」和模型代号，比如 `CC Club / Sonnet 4.6 (1M)`。

<Callout type="info">
  这个字段**只影响列表显示**，不会进入实际请求，写中文完全 OK。
</Callout>

### 官网链接

**留空**。CC Club 不需要这个字段，留空不会触发任何校验问题。

### API（也就是 API Key）

把你在 [获取 API Key](/getting-started/get-api-key) 页面拿到的 Key 粘贴进来。

<Callout type="warning">
  Key 形如 `cr_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`，**首尾不要带空格**。CC Switch 不会把它明文回显——保存后再次进入会被遮蔽显示，这是预期行为。
</Callout>

### 请求地址（Base URL）

```
https://claude-code.club/api
```

这是 CC Club 的默认地址，**直连延迟 < 100ms 时最快**。如果你的网络访问默认地址明显偏慢，可以换成下表中的回国优化节点：

| 地址 | 适用情况 |
|---|---|
| `https://claude-code.club/api`     | 默认（直连最快）             |
| `https://jp.claude-code.club/api`  | 日本节点（阿里云，回国优化） |
| `https://hk.claude-code.club/api`  | 香港节点（阿里云，回国优化） |
| `https://sz.ai-code.club/api`      | 深圳节点（国内中转出境）     |

### API 格式

下拉选择 **`Anthropic Messages（原生）`**。

<Callout type="info">
  CC Club 接口与 Anthropic 官方协议**完全兼容**，**必须**选原生 Messages 协议。如果错选成 OpenAI Chat Completions，会因为请求体结构不同直接 4xx 报错。
</Callout>

### 模型区域

**留空**。

不填的原因是：模型由下一项「配置 JSON」里的 `model` 字段统一指定，留空后 CC Switch 会以 JSON 为准，避免两处冲突造成误用。

### 配置 JSON（完整版）

这是整个表单的核心。**整段**复制到 JSON 输入框，再把 `ANTHROPIC_AUTH_TOKEN` 的空字符串替换为你自己的 API Key：

```json
{
  "effortLevel": "medium",
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "",
    "ANTHROPIC_BASE_URL": "https://claude-code.club/api"
  },
  "model": "sonnet[1m]"
}
```

**字段含义**：

| 字段 | 含义 | 修改建议 |
|---|---|---|
| `effortLevel` | Claude 思考强度档位（`low` / `medium` / `high`） | 通常保持 `medium`；任务复杂时再升 `high`         |
| `env.ANTHROPIC_AUTH_TOKEN` | 注入到 Claude Code 进程的 API Key 环境变量    | **必改**：填你自己的 Key                         |
| `env.ANTHROPIC_BASE_URL`  | 注入到 Claude Code 进程的 Base URL 环境变量   | 与上方「请求地址」保持一致即可                    |
| `model` | Claude Code 启动时默认使用的模型                  | `sonnet[1m]` = Sonnet 4.6 + 1M 上下文，性价比首选 |

<Callout type="warning">
  JSON 不接受**尾随逗号**——上方片段结尾的 `}` 之前不能多任何 `,`，否则保存时会校验失败。
</Callout>

</Steps>

## 保存并验证

<Steps>

### 点击右下角「保存」

CC Switch 会校验 JSON 合法性，通过后这条供应商出现在左侧列表中。

### 单击这条供应商卡片激活它

CC Switch 是「主动选中谁就用谁」——卡片前面出现勾选标记后，CC Switch 会把对应配置写入 Claude Code 的 `~/.claude/settings.json`。

### 在终端跑一次 Claude Code

```bash
claude --version
claude "用一句话解释什么是 vibe coding"
```

秒级返回一段中文，说明 Key、Base URL、模型链路都对得上。

</Steps>

<Callout type="success">
  跑通这一步，**CC Switch + Claude Code + CC Club** 整条链路就通了。以后想换节点 / 换模型 / 多账号切换，回 CC Switch 一键搞定，不再需要手改任何配置文件。
</Callout>

## 常见问题

### Q：保存时提示 JSON 校验失败？

两个最容易踩的坑：

1. **结构残缺**——少了某个 `}` 或 `"`，对照本页 [完整 JSON 片段](#配置-json完整版) 重抄一遍
2. **尾随逗号**——某个键值对结尾多了 `,`，JSON 不接受

### Q：保存后跑 `claude` 仍报「Invalid API key」？

先确认这条供应商**前面有勾选标记**（高亮态）。CC Switch 的逻辑是"主动选中才生效"——保存只是建立配置，**不等于激活**。

### Q：想再配置一个 Claude 模型（比如 Opus）怎么办？

不用改这条供应商，**复制一份**这条配置，把 `model` 改成 `opus[1m]` 即可。CC Switch 允许任意多条同源供应商共存，需要哪一条就单击切换。

### Q：可以同时启用多条 Claude 供应商吗？

不行。Claude Code 在任何时刻**只读取**当前激活的那一条配置——CC Switch 切换的是"哪条生效"，不是"全部并行"。如果要并行使用不同模型，开多个终端 / 项目 + 多个 settings.json 才能实现。
